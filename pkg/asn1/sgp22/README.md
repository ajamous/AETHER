# SGP.22 ASN.1 modules

This directory holds the ASN.1 module definitions for GSMA SGP.22
(Consumer RSP Technical Specification) and the build glue that turns
them into machine-usable codecs.

## What lives here

```
pkg/asn1/sgp22/
├── README.md          # this file
├── Makefile           # `make gen` regenerates everything
├── modules/           # vendored .asn module files (from SGP.22 Annex B)
│   └── PEDefinitions.asn
├── generated/         # generated artifacts (gitignored)
└── go/                # Go package wrapping the codec
    ├── doc.go
    ├── types.go       # hand-written Go types using encoding/asn1
    └── types_test.go  # encode/decode round-trip tests
```

## Two codec paths

SGP.22's ASN.1 schema uses constructs that Go's `encoding/asn1` does
not fully cover (parameterized types, certain constraint expressions).
We support two codec paths and choose per type:

1. **Pure Go codec** for types that fit cleanly in Go's
   `encoding/asn1` model. Simpler, no cgo, easy to debug. Used for
   the most-commonly-touched types (BPP envelope, metadata).
2. **asn1c-generated C codec, called via cgo** for full-fidelity
   coverage of types where Go's codec can't represent the schema
   correctly. Generated by `make gen`.

When in doubt, prefer the pure Go path. If a round-trip test fails
because Go's codec mis-encodes a constraint, fall back to the asn1c
path for that type and document the reason in the type's doc comment.

## Vendoring the spec modules

The ASN.1 module text comes from **GSMA SGP.22 Annex B**. We do not
redistribute the full spec text; we vendor only the ASN.1 modules,
which are operationally necessary and routinely embedded in
implementations. Each vendored file carries a header noting:

- The spec section it came from
- The spec version it matches
- A pointer to the GSMA publication URL

When vendoring a module:

```
1. Download the SGP.22 spec from the GSMA publications site
2. Copy the ASN.1 module text from Annex B into modules/
3. Add the standard header (see modules/PEDefinitions.asn for the
   pattern)
4. Run `make gen`; verify the generated artifacts compile
5. Update the round-trip tests
6. Update the SGP.22 coverage matrix
```

If a module is updated by a new SGP.22 version, treat it like any
other dependency upgrade: bump the version pinned in this README,
regenerate, run the test suite, fix breakage.

## Regenerating

From the repo root:

```
make gen
```

Or, scoped to this directory:

```
make -C pkg/asn1/sgp22 gen
```

`asn1c` must be on PATH. On macOS: `brew install asn1c`. On
Debian/Ubuntu: `apt-get install asn1c`. From source:
[github.com/vlm/asn1c](https://github.com/vlm/asn1c).

## Status

Phase 1 services need them, not speculatively.
